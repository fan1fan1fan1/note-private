#### 2.基础名词预习

1. GET 请求：向服务器索要数据（我们练习全部使用 GET）
2. Headers 请求头：模拟浏览器访问，防止网站拒绝脚本
3. 状态码
   - 200：请求成功
   - 404：页面不存在
   - 403：服务器拒绝访问（反爬拦截）
4. `response.text`：网页源代码（文本）
5. `response.content`：二进制数据（图片、压缩文件下载专用）



#### 3.get post区别

  1.定义

- GET：获取数据（从服务器拿东西，不提交数据修改服务器内容）
- POST：提交数据（向服务器发送表单、账号密码、上传信息）

```python
# GET
resp = requests.get(url, headers=headers)
# POST
resp = requests.post(url, headers=headers, data=xxx)
```

2. 关键差异对照表

| 对比项   | GET                                         | POST                               |
| -------- | ------------------------------------------- | ---------------------------------- |
| 作用     | 请求、查询、获取页面 / 资源                 | 提交表单、上传数据、登录、发布内容 |
| 参数位置 | 参数拼在URL 地址里面例：`search?keyword=猫` | 参数放在请求体(body)，URL 看不见   |
| 数据大小 | 受 URL 长度限制，不能传大量数据             | 理论无上限，适合传递大量内容       |
| 缓存     | 浏览器默认缓存 GET 请求                     | 默认不缓存                         |
| 安全性   | ❌ 明文参数暴露在网址，不能传密码            | ✅ 参数不在地址栏，适合账号密码     |
| 幂等性   | 多次刷新结果一样，不会产生副作用            | 多次提交可能重复发帖、重复提交表单 |

3. 举例直观理解

   GET 场景（你第三梯队现在练习全部是 GET）

   ​	https://www.baidu.com/s?wd=python

   ​	wd=python

##### 基础API

`img.mode` Pillow 读取图片，用来标记图片色彩模式的属性。

属性:

​	"RGB"     图片由 3 套数据组成：红色、绿色、蓝色。只能显示彩色，不能有透明。普通 jpg 图片都是这个。

​	"RGBA"   R 红、G 绿、B 蓝、A 透明度。多了一套透明度数据。所以图片可以有透明背景。绝大多数透明 PNG 是这个类型。

​        "L"          只有 1 套数据：灰度。就是黑白图片，没有透明。

​	"LA"       灰度 + 透明度。黑白图片，还能拥有透明背景，日常很少见到。

​	"P"         调色板模式。不直接记录每个像素颜色。自带一张颜色清单，像素只写清单编号。部分 PNG、GIF 动图是这个模式，有可能带透明。

##### TCP

简单大白话：TCP 是规范，两台电脑依照这个规范建立通道互发消息，称为 TCP 通信。

TCP 是互联网最常用的通信规则（协议）。作用：让两台电脑之间稳定互相收发数据。
可以这么理解：两台电脑想要对话，TCP 就是一套约定好的沟通规矩，先建立连接（先打招呼确认对方在线），数据有序传送，丢包会自动重传，保证消息完整送达，对话结束正常断开连接。

对比你爬虫用的 HTTP，HTTP 也是基于 TCP。爬虫流程：电脑→网站服务器，发一次请求、收到结果就断开（短连接）。而我们写的 TCP 程序，连接建立后，可以持续来回反复发多条消息。

两个核心角色，服务端 server：守在电脑上，等待别人来连接（相当于门店，开门等人上门），客户端 client：主动发起连接去找服务端（顾客主动进店）。想要通信必须满足两点，服务端电脑 IP 地址，双方使用同一个端口号（好比门店门牌号）。

Python 代码里的关键现象解释，网络不能直接传输中文 / 字符串，只能传字节 (bytes)，msg.encode ("utf-8")  发送：字符串 → 字节，data.decode ("utf-8") 接收：字节 → 字符串。

TCP 和爬虫 HTTP 直观区别，HTTP（requests 爬虫）单次请求→响应，完事立刻断开。只能客户端主动发问，网站不能主动给你推送消息。原生 TCP socket 连接建立之后，双方随时可以互相发消息，长连接。适用场景：两台电脑实时互传消息、文件推送。

简易运行逻辑，先运行服务端，程序开始监听端口，等待连接，再运行客户端，主动去找服务端 IP + 端口，建立通道，客户端发送文字 → 服务端接收，服务端可以回复文字 → 客户端接收。

简单注意点，127.0.0.1 代表本机，只允许自己电脑内部测试；局域网其他电脑连接，需要填写服务端真实内网 IP；Windows 防火墙大概率会拦截端口，连不上的时候检查防火墙。

补充区分概念，TCP：可靠、消息不会乱序、丢失自动重传（我们练习用这个），UDP：无连接，速度快，但有可能丢消息，脚本自动化很少用到。

##### pyinstaller 

pyinstaller 打包，把 py 脚本变成 exe 程序

```python

```



###### 基础打包命令

pyinstaller -F 你的脚本名.py

###### 参数解释

-F 生成单个 exe 文件，所有依赖全部打包进一个程序。
-w 运行的时候不弹出黑色控制台窗口。GUI 弹窗脚本可以加 - w；打印日志的脚本不要加 - w，加了看不到 print 输出。
-i 可以设置程序图标，可选。

###### 解释

pyinstaller 是命令行工具，不是写在 python 代码里面的。

1. 先有.py执行文件

2. 在文件路径位置输入powershell回车进入

3. 输入pyinstaller -F -w xxxx.py  或者 python -m PyInstaller -F -w xxxx.py

4. 打包结束后产出 

   1. test.spec （脚本同目录，配置文件）

   2. build 文件夹（整个文件夹）

   3. dist 文件夹（整个文件夹）  dist 里面：test.exe 真正能用的程序

        build 文件夹：中间编译缓存，直接删掉。
        test.spec：打包的配置文件，不用管，可以删掉。
        只保留 dist\test.exe 就够，别的全部可以删除。

5. 生成的exe无法修改图标 想改变图标图片只能在生成时就指定

   Windows 的 exe 图标只认后缀为`.ico`的文件

   1，找一张你想要的图片

   2，打开浏览器搜 png 转 ico，在线网站，上传图片，下载得到 xxx.ico 文件。不要直接修改后缀

   3，把这个下载好的 xxx.ico，放到你的 py 脚本同一个文件夹。

   4，powershell 输入打包命令，-i 后面写你的 ico 文件名。

   示例：图标文件叫 a.ico，脚本叫 clock.py

   ```
   python -m PyInstaller -F -w -i a.ico clock.py
   ```
